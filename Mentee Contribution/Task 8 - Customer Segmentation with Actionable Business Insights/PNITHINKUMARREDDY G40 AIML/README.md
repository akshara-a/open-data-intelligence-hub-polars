# Mini Project 4 — Customer Segmentation with Actionable Business Insights

## Contents
```
MiniProject4_Customer_Segmentation.ipynb   Main notebook (EDA -> clustering -> regression -> classification -> comparison)
generate_dataset.py                         Offline fallback data generator (same schema as the real Kaggle dataset)
data/customer_segmentation_data.csv         Dataset used for this run
Decision_Log.md                             Every assumption / schema-mapping decision, explained
Customer_Segment_Report.md                  Segment names, characteristics, revenue share, business actions
Model_Comparison_Report.md                  Final mentor-validated report (all required sections)
Mentor_Evaluation_Checklist.md              Requirement-by-requirement checklist
outputs/                                    Charts, processed dataset, comparison table (generated by the notebook)
models/                                     Saved model + scaler .pkl files (generated by the notebook)
```

## Dataset
**Kaggle:** https://www.kaggle.com/datasets/fahmidachowdhury/customer-segmentation-data-for-marketing-analysis
(Customer Segmentation Data for Marketing Analysis, by Fahmida Chowdhury — 2,000 rows, 9 columns)

## How to run
1. `pip install pandas numpy scikit-learn matplotlib seaborn joblib kagglehub`
2. Open `MiniProject4_Customer_Segmentation.ipynb` and run all cells.
   - Cell 2 tries to download the real dataset from Kaggle via `kagglehub` first.
   - If Kaggle isn't reachable (no internet / no API token), it automatically falls back to
     `generate_dataset.py`, which reproduces the same column names, dtypes, and value ranges, so every
     later step (EDA, clustering, modeling, tuning) runs identically either way.
3. Outputs (charts, processed CSV, comparison table) are written to `outputs/`; trained models to `models/`.

## What's inside the notebook
1. Data loading (Kaggle → fallback)
2. EDA (distributions, outlier boxplots, correlation heatmap)
3. Preprocessing & schema alignment (RFM + engagement feature engineering)
4. **Clustering (primary)** — K-Means with Elbow Method + Silhouette Score, PCA visualization, segment profiling
5. Regression — Ridge Regression predicting `CustomerRating`, tuned with `GridSearchCV`
6. Classification — Logistic Regression predicting `PurchaseLikelihood`, tuned with `GridSearchCV`
7. Model comparison table
8. Business interpretation & final recommendation

See `Model_Comparison_Report.md` for the full write-up, `Customer_Segment_Report.md` for the per-segment
business actions, and `Decision_Log.md` for why each schema/engineering choice was made.
